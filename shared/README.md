# shared/

前后端**共同使用**的数据定义。

## 为什么存在

走本地优先架构后，默认的训练部位 / 动作 / 补剂必须同时存在于两个地方：

- 后端：`prisma/seed.ts` 用它初始化 SQLite
- 前端（Phase 3 起）：打进前端包，手机第一次打开、没有网络时也能列出「胸 / 背 / 肩」

如果两边各写一份，早晚会漂移。所以这里只定义**一份**，两边都读它。

## 约束

- 只放**数据**，不放代码，保持纯 JSON，两个运行环境都能直接读。
- 改这里 = 改默认数据。改动后需要重新执行 `npm run db:seed`（seed 只新增，不覆盖已有记录）。

## 补剂的 units（可选单位）

`supplements.json` 里每条补剂可以带一个 `units` 数组，表示这个补剂**允许用哪些单位记录**
（第一项是默认值）：

```json
{ "name": "蛋白粉", "unit": "g", "units": ["g", "勺"] }
```

蛋白粉 / 增肌粉这类「按勺吃、也可以按克称」的补剂，记录时可以直接点「勺」。
前端在 `syncDefaults` 里会把新增的单位补进老设备（只补不删），后端 seed 同样只补空的 `units`。
